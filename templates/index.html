5 · Filters (applied to every enumerated product before docking)

PAINS / REOS hard-reject before docking. MW / logP: leave blank to disable. Core RMSD guard: reject any docked pose whose placed fragment core drifts more than this from the bound reference (MCS match to the conserved core) — this is what holds the fragment's binding mode now that the dock is a real search, so it has to be tight: the core is rigid, so its RMSD tracks how far it has turned, and a core turned fully perpendicular in place still averages only ~1.5 Å. The default is 2.0 Å, which is admissive on purpose: every pose is annotated with core_rmsd and core_max_dev so you can filter on drift afterwards, while a pose the guard rejected is gone unless you re-dock. Tighten to 0.8 Å (~30°) or 0.5 Å (~20°) only when the anchor is large enough to hold it — on a small, flat core a tight guard keeps the few percent of products that sit closest to the fragment and throws away the rest. Measure drift on: by default the guard judges the whole conserved core. Name a part of it (SMILES or SMARTS) to judge only that — growing from a modified fragment, put the original fragment here: the build still pins the whole modified core (it is the molecule being grown), while the binding mode being guarded stays the one that was solved. core_rmsd is then reported over those atoms too. Untick and nothing is rejected on placement; either way core_rmsd, core_max_dev and min_receptor_dist (closest heavy-atom approach to the receptor) are measured and written to every pose, so you can filter on them afterwards. Energy filter: reject a pose whose minimizedAffinity is above the max — above zero it is repulsive, so whatever it is, it isn't binding. GNINA's search rarely returns one; this is the check for when it does, which a CNN score field would not show.
